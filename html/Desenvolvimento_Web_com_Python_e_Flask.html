Métodos e códigos de status

O método diz o que o cliente quer fazer; o status diz como foi o resultado.

Métodos mais usados

MétodoIntençãoExemplo
GETBuscar / exibir algo. Não deve alterar dados.Abrir a lista de contatos
POSTEnviar dados para criar ou processar.Cadastrar um contato
PUTSubstituir / atualizar um recurso.Editar um contato (APIs)
DELETERemover um recurso.Excluir um contato (APIs)

Formulários HTML só enviam GET ou POST. PUT e DELETE aparecem em APIs chamadas por JavaScript.

Códigos de status

CódigoSignificado
200OK, deu certo
201Criado com sucesso
302Redirecionamento: vá para outra URL
400Requisição inválida (dados faltando)
404Não encontrado
405Método não permitido nesta rota
500Erro interno no servidor (bug no código)

Regra prática: 2xx sucesso, 3xx redirecionamento, 4xx erro do cliente, 5xx erro do servidor.

form.addEventListener('submit', (evento) => {

document.querySelectorAll('.btn-excluir').forEach((botao) => {

O motor: por que usar Flask?

Um micro-framework para construir o back-end sem mágica excessiva.

✓

É leve. O núcleo cabe na cabeça: você entende o essencial da web passo a passo.

✓

Usa Python. Transição natural para quem já conhece a linguagem.

✓

Ensina conceitos reais. Rotas, templates, formulários e arquivos estáticos existem em qualquer framework.

✓

Cresce com extensões. Banco de dados, login e formulários são adicionados só quando necessários.

Micro vs. completo: o Django já vem com banco, admin e autenticação. O Flask começa mínimo, ideal para aprender o que cada peça faz.

from flask import Flask, request

app = Flask(__name__)

@app.route('/buscar')
def buscar():
    termo = request.args.get('q', '')
    return f'Você buscou por: {termo}'

@app.route('/mensagem', methods=['GET', 'POST'])
def mensagem():
    if request.method == 'POST':
        texto = request.form['texto']
        return f'Recebido: {texto}'
    return '''
        <form method="POST">
          <input name="texto">
          <button>Enviar</button>
        </form>
    '''

from flask import Flask, jsonify, redirect, url_for, abort

app = Flask(__name__)
contatos = [{'id': 1, 'nome': 'Ana'},
            {'id': 2, 'nome': 'Bruno'}]

@app.route('/api/contatos')
def api_contatos():
    return jsonify(contatos)

@app.route('/api/contatos/<int:id>')
def api_contato(id):
    for c in contatos:
        if c['id'] == id:
            return jsonify(c)
    abort(404)

@app.route('/inicio')
def inicio():
    return redirect(url_for('api_contatos'))

→

Cada argumento nomeado (usuario=, notas=) vira uma variável dentro do template.

{{ }}

Imprime o valor de uma expressão. usuario.nome acessa a chave do dicionário.

|

Filtros transformam o valor: upper, length, sum, round. Resultado: COMPUTAÇÃO, 3, 8.2.

O servidor processa o Jinja e entrega apenas HTML puro ao navegador. Ele também escapa o texto automaticamente: um <script> digitado pelo usuário vira texto inofensivo.

from flask import Flask, render_template, request, redirect, url_for

app = Flask(__name__)
contatos = []  # lista em memória

@app.route('/')
def index():
    return render_template('index.html', contatos=contatos)

@app.route('/adicionar', methods=['POST'])
def adicionar():
    nome = request.form['nome']
    email = request.form['email']

    contatos.append({'nome': nome, 'email': email})

    return redirect(url_for('index'))

if __name__ == '__main__':
    app.run(debug=True)

O fluxo de dados: padrão PRG

Post / Redirect / Get, o ciclo profissional para submissão de formulários.

Sem PRG: a página exibida é a resposta do POST. Ao apertar F5, o navegador repete o POST e o contato é cadastrado duas vezes.
Com PRG: a página exibida é a resposta de um GET. O F5 apenas recarrega a lista, sem efeitos colaterais.

import json
from pathlib import Path

ARQUIVO = Path('contatos.json')

def carregar_contatos():
    if ARQUIVO.exists():
        texto = ARQUIVO.read_text(encoding='utf-8')
        return json.loads(texto)
    return []

def salvar_contatos(contatos):
    texto = json.dumps(contatos, ensure_ascii=False, indent=2)
    ARQUIVO.write_text(texto, encoding='utf-8')

contatos = carregar_contatos()  # ao iniciar o servidor

Erros comuns e como resolver

Quase todo iniciante encontra estes. Leia a mensagem de erro: ela costuma dizer exatamente o que falta.

MensagemCausa provávelSolução
ModuleNotFoundError: No module named 'flask'Ambiente virtual não ativadoAtive o venv e confira o (venv) no terminal
jinja2.exceptions.TemplateNotFoundArquivo fora da pasta ou nome erradoColoque o HTML em templates/, ao lado do app.py
405 Method Not AllowedFormulário faz POST, mas a rota só aceita GETAdicione methods=['POST'] na rota
400 Bad Requestrequest.form['x'] com um name diferente no HTMLConfira os nomes ou use request.form.get('x')
werkzeug.routing.BuildErrorurl_for com nome de função inexistenteUse o nome da função, não o caminho da URL
Address already in useOutro servidor ocupa a porta 5000Feche o outro terminal ou use app.run(port=5001)

Ferramentas de depuração: a página de erro do modo debug, print() no terminal do servidor e a aba Rede (F12) no navegador.
